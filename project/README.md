### 2. 关联

实体间的关联：

- 对于一个`User`，其拥有一个购物车`cart`，拥有多个收藏物品`favorites`、地址`addresses`、订单`orders`；
- 对于一个`product`，其拥有一个`image`，拥有很多`cart_items`、`favorites`；
- 对于一个`cart`，其属于一个`user`，拥有很多`cart_items`，并通过`cart_items`拥有很多`products`；
- 对于一个`order`，其属于一个`user`，拥有很多`order_items`；
- `item`类别的实体具有和`product`的关联，用于记录存放着哪个商品的信息



### 3. 部分细节

登陆注册使用了`devise`进行身份认证，并修改了认证关键词，使用用户名进行登录；

用户端和管理员端对于订单的交互，通过属性`status`来完成，针对不同的`status`取值来决定双方各自可以进行的操作；

由于购物车和订单中的商品与商品本身有较强的联系，因此设计了`cart_item`和`order_item`来方便关系的建立，而`favorite`只是商品的另一展示形式，因此没有做类似的处理；

管理员添加商品时，可以规定销量，但提交商品后的销量只会和用户的有效订单挂钩；

商品下架时库存自动清零，若要重新上架，则需要重新编辑库存信息。



## 二、使用手册

进入系统，首页简要介绍了系统中实现的功能，并提供了一个用户账号和一个管理员账号，用户账号事先进行了相关操作，登录可以直观感受实现的大致功能。

### 1. 注册与登录

与正常的注册登录功能没有区别，注册页面可以选择注册身份：管理员或普通用户，登录后享受不同视图。



### 2. 所有商品（用户端）

以用户身份登录后，在所有商品界面，可以查看当前**上架**的所有商品，下架商品不会对用户展示。

在该界面，用户可以

- 点击查看详情查看商品的详细信息
- 点击商品栏中的购物车按钮将该商品加入购物车中（1件商品）
- 点击收藏按钮将商品加入收藏夹中



### 3. 购物车

购物车中存放着所有加入的产品，用户可以

- 调整商品数量，自动更新商品总价格
- 点击结算后自动**清空购物车**，并尝试生成一个订单，用户可以选择支付或者暂存订单。（详见订单部分）



### 4. 收藏夹

收藏夹中存放着所有收藏的产品

- 点击卡片进入商品的详细信息界面
- 点击移除收藏将该收藏删去



### 5. 地址管理

对于每一个用户，必须至少有一个地址，才能进行生成订单的相关操作。在该界面，用户可以

- 添加新地址，输入姓名、联系方式、具体地址等信息，还可以设置是否为**默认地址**（在生成订单时默认地址会被自动填充进对应字段）
- 已有地址可以进行修改、删除操作



### 6. 订单相关（用户端）

如购物车部分所述，点击结算后，用户在生成订单界面选择已有地址，可以选择**暂存订单**或**去支付**：

- 如果订单中的商品存在**库存不足**的情况，则不会生成订单
- 暂存订单会将当前订单信息保存，订单状态为**待支付**；去支付订单会产生有效订单，状态为**已支付**
- 对于**已支付**订单，商品对应的**销量**会产生对应数目的增加
- 两种订单都会被加入我的订单中，供用户查看

在我的订单界面，存放着用户的所有订单，订单状态包括以下5种：

- 待支付
- 已支付
- 已发货
- 已收货
- 已完成

点击查看详情，可以查看订单的详细信息，对用户而言：

- 若订单状态为“待支付“，则可以点击**去支付**，订单状态转变为“已支付“
- 若订单状态为“已发货”，则可以点击**确认收货**，订单状态转变为“已收货”



### 7. 商品管理（管理端）

以管理员身份登录后，在所有商品界面，可以查看当前**上架**和**下架**的所有商品。

在该界面，管理员可以：

- 填写商品名称、描述、库存、价格等信息，新增商品

- 点击查看详情查看商品的详细信息
- 对商品信息进行编辑
- 将已有商品下架，商品销量自动清0
- 将已下架商品重新上架



### 8. 订单相关（管理端）

管理员在订单管理界面可以查看所有用户的所有订单，对于不同状态的订单可以进行不同的操作：

- 若订单状态为“已支付“，则可以进行**发货**，订单状态转变为“已发货“
- 若订单状态为“已收货”，则可以标记为**完成**，订单状态转变为“已完成”
- 若订单状态为“待支付”或“已完成”，则可以将**订单删除**（保证不删除正在生效订单）
